# 직무 전환 취업 리서치 레이더

새 자료의 양보다 **무엇이 바뀌었고 사용자가 취업 준비에 어디에 쓸 수 있는지**를 분명히 한다.

## 기본 사용자 맥락

- 콘텐츠 디자이너 경력 5년 8개월을 보유하고 프로덕트 디자이너로 전환 중이다.
- 프로덕트 디자이너 직함으로 일한 경험은 아직 없다.
- 관심 산업은 금융·증권·핀테크·결제·리워드 광고·커머스다.
- 우선 회사는 NH투자증권과 LINE Pay다. 요청에 다른 회사가 있으면 함께 조사한다.
- 기존 경력을 신입 경험처럼 지우거나 프로덕트 디자인 직접 경력처럼 과장하지 않는다.

## 실행 전에 확인

- 기존 Notion 리서치 데이터베이스의 URL, 최근 확인일, 저장된 원문 URL을 확인한다.
- 사용자가 기간을 정하지 않으면 최근 7일을 먼저 보고, 중요한 변화는 최근 30일까지 넓힌다.
- 현직자 인터뷰와 디자인 시스템 운영 맥락은 최근 2년까지 허용하되 오래된 참고라고 표시한다.
- 자동 실행을 요청하지 않았다면 한 번 수동으로 조사한다. 매일 아침 실행은 별도 자동화 기능이다.

## 조사 범위

### 산업·회사

- 새 채용공고와 기존 공고의 모집 상태 변경
- 정책·규제와 시행일
- 시장·거래·결제 구조의 변화
- 회사의 신규 제품·기능·사업 전략
- AI·오픈 API·자동화
- 사용자 보호, 신뢰, 개인정보, 오류 복구

### 프로덕트 디자인 직무

- 실명 현직자 인터뷰와 실제 프로젝트 회고
- 디자인·기술·제품 블로그
- 디자인 시스템 구축·운영·개발 연동
- Figma와 디자인 도구 업데이트
- AI 프로토타이핑과 구현 사례
- 사용자 리서치, 데이터 검증, 협업 방식
- 포트폴리오·과제·채용 평가 기준
- 최근 자료를 실제 제품 상황으로 바꾼 논리적 사고 훈련

각 범위를 검색했는지 기록하되 자료 개수를 맞추기 위해 의미 없는 글을 채우지 않는다.

## 근거와 최신성

[조사·검증 기준](references/research-and-verification.md)을 읽고 따른다.

- 공식 원문을 우선하고 게시일과 실제 사건 발생일을 구분한다.
- 채용공고는 공식 페이지를 열어 모집 상태와 마감을 확인한다.
- 인터뷰는 작성자·발표 당시 소속·직무·게시일을 확인한다.
- 새 원문 URL이면 신규 자료, 같은 URL의 상태·내용이 달라졌으면 업데이트로 구분한다.
- 기존 자료와 변화가 없으면 중복 저장하지 않는다.
- 공식 사실, 기업 주장, 조사자의 직무 해석을 섞지 않는다.

## 결과 작성

[결과·Notion 템플릿](references/output-and-notion-template.md)을 읽고 같은 구조로 작성한다.
사용자가 사고 훈련을 원하거나 매일 활용할 구성을 요청하면 [프로덕트 사고 훈련](references/product-thinking-practice.md)도 읽는다.

전체 결과에는 다음이 보여야 한다.

1. 오늘의 핵심 변화 3줄
2. 새 공고 또는 상태 변경
3. 산업·회사·제품 변화
4. 새 현직자 인터뷰와 실무 블로그
5. 디자인 시스템·Figma·AI 변화
6. 콘텐츠 디자인 경력과 연결할 후보
7. 이력서·포트폴리오·면접 활용
8. 오늘 실행할 행동 하나
9. 오늘의 프로덕트 디자이너 사고 훈련
10. 새 자료가 없는 범위와 확인 필요 항목

## 직무 전환 연결

- **직접 증명:** 사용자가 제공한 실제 경력에서 문제·역할·행동·결과가 확인됨
- **연결 가능:** 콘텐츠 디자인의 정보 구조·사용자 행동·가이드 운영·협업·성과 개선과 인접함
- **보완 필요:** 제품 전체 흐름·동작 프로토타입·사용자 검증·제품 지표·개발 구현·금융 안전의 증거가 없음

이력서나 프로젝트 원문이 없으면 직접 증명을 확정하지 않는다. 모든 문장에 ‘후보·사용자 확인 필요’를 표시하고 실제로 하지 않은 일을 생성하지 않는다.

## 저장과 전송

- 검증된 새 자료만 기존 Notion 산업·직무 리서치 데이터베이스에 한 행씩 저장한다.
- 속성만 채우지 않고 페이지 본문에도 변화·직무 의미·취업 활용·주의점·원문을 적는다.
- 같은 원문은 중복 저장하지 않고 기존 행의 변경점과 확인일을 갱신한다.
- 사용자가 읽거나 활용했다고 확인하기 전에는 사용상태를 완료로 바꾸지 않는다.
- Slack은 채널과 전송문을 사용자가 승인한 경우에만 보낸다. 그 전에는 미리보기만 만든다.
- 로컬 결과와 작업일지는 기존 파일을 덮어쓰지 않는 워크숍 규칙을 따른다.
